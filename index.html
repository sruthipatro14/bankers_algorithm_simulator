What is Banker's Algorithm?

Banker's Algorithm is a resource allocation and deadlock avoidance algorithm used in operating systems. It checks whether granting resource requests keeps the system in a safe state — one where at least one safe sequence exists in which all processes can complete.

  • It avoids deadlock by ensuring that resource allocations keep the system in a safe state.
  • It keeps track of the resources each process needs and the resources currently available.

Components of Banker's Algorithm

Let n be the number of processes in the system and m be the number of resource types.

Available

Available

A one-dimensional array of size m indicating the number of available resources of each type.

Available[j] = k means there are k instances of resource type Rj currently available.

Max

Max

A two-dimensional array of size n × m that defines the maximum demand of each process in the system.

Max[i, j] = k means process Pi may request at most k instances of resource type Rj.

Allocation

Allocation

A two-dimensional array of size n × m that defines the number of resources of each type currently allocated to each process.

Allocation[i, j] = k means process Pi is currently allocated k instances of resource type Rj.

Need

Need

A two-dimensional array of size n × m that indicates the remaining resource needs of each process.

Need[i, j] = k means process Pi currently needs k additional instances of resource type Rj.

Need[i, j] = Max[i, j] − Allocation[i, j]

Allocation specifies the resources currently allocated to process Pi, while Need specifies the additional resources that process Pi may still request to complete its task.

Key Concepts in Banker's Algorithm

Safe State

There exists at least one sequence of processes such that each process can obtain its needed resources, complete its execution, release its resources, and allow the remaining processes to complete — without entering a deadlock.

Unsafe State

An unsafe state does not necessarily mean that a deadlock has already occurred. It means the system cannot guarantee that all processes will complete without potentially causing a deadlock.

Safety Algorithm

The safety algorithm checks whether the system is in a safe state, meaning all processes can complete without causing deadlock.

1

Initialize

  • Work = Available
  • Finish[i] = false for all processes, because none have finished yet.
2

Find an eligible process

Find a process Pi for which both conditions hold:

  • Finish[i] = false
  • Need[i] ≤ Work

If Need[i] ≤ Work, assume Pi receives the remaining resources it requires, completes execution, and releases all its allocated resources.

3

Update resources

  • Work = Work + Allocation[i]
  • Finish[i] = true
  • Repeat Step 2 for the remaining unfinished processes.
4

Determine the result

  • If all processes have Finish[i] = true, the system is in a safe state.
  • If no eligible process can be found while some remain unfinished, the system is unsafe.

The algorithm simulates process completion to verify that all processes can finish safely.

Resource Request Algorithm

This algorithm determines whether a process's resource request can be safely granted without putting the system into an unsafe state.

1

Check the process's remaining need

If Request[i] > Need[i], reject the request — the process has exceeded its declared maximum demand.

2

Check resource availability

If Request[i] > Available, the process must wait until the requested resources become available.

3

Temporarily allocate resources

If both checks pass, temporarily update:

  • Available = Available − Request[i]
  • Allocation[i] = Allocation[i] + Request[i]
  • Need[i] = Need[i] − Request[i]
4

Run the Safety Algorithm

  • If the resulting state is safe, grant the request.
  • If the resulting state is unsafe, roll back all temporary changes and make the process wait.

The resource-request algorithm ensures that resources are granted only when the system remains safe, helping prevent deadlock.
